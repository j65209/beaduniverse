중국 발주, ERP 연동, 사내 자료 관리를 하나의 화면에서 다룬다.

> **라이브 URL** · https://j65209.github.io/beaduniverse/
> **저장소** · https://github.com/j65209/beaduniverse

## 1. 프로젝트 개요

- **이름** · 브라이트비드 오피스 (Brightbeed Office)
- **목적** · 중국 발주 + 사내 운영 데이터를 한 화면에서 보고/관리
- **호스팅** · GitHub Pages — `.github/workflows/pages.yml` 이 main 푸시마다 배포 (Settings → Pages → Source: GitHub Actions).
  배포는 한 줄로 세우고 일시 오류는 재시도한다. raw.githubusercontent 로 읽는 파일(업무일지 백업·광고 시트·기획전·환율)만 바뀐 커밋은 배포하지 않는다 — 목록은 워크플로 `paths-ignore`.
- **보안** · 6자리 PIN + IP 화이트리스트 (브라우저 localStorage 기억)

## 9. 업무일지 저장 구조 (v0.5 — 줄 단위 실시간)

업무일지는 **Supabase `diary_items` 테이블에 "한 줄 = 한 행"** 으로 저장된다.
예전에는 전 직원 일지가 `data/diary.json` 파일 하나였고, 한 글자만 고쳐도 파일을
통째로 다시 써서 **동시에 쓰면 남의 줄이 지워지는** 사고가 있었다. 지금은 내가 고친
줄만 서버로 가므로 남의 줄을 덮어쓸 방법 자체가 없다.

| 항목 | 값 |
|---|---|
| 프로젝트 | `브라이트비드오피스` (`ckyjkxbqsyjoqpuqwoce`) |
| 테이블 | `diary_items` (본문) · `diary_item_history` (전 변경 이력) |
| 실시간 | `supabase_realtime` 퍼블리케이션 등록 — 한 줄 고치면 전 직원 화면에 즉시 반영 |
| 백업 | 10분마다 `data/diary.json` 스냅샷 자동 커밋 (사람이 읽을 수 있는 백업) |

### 유실 방지 안전장치 9종

1. **로컬 우선** — 타이핑은 즉시 localStorage 에 저장. 서버 전송은 그 다음.
2. **전송 대기열** — 못 보낸 줄은 대기열에 남고, 대기열도 localStorage 에 보관.
   창을 닫든 인터넷이 끊기든 다음 접속 때 자동 재전송.
3. **시각 도장(`client_ts`)** — 서버 트리거가 더 오래된 편집을 거부한다.
4. **소프트 삭제** — 삭제는 `deleted_at` 표시만. 행은 남는다.
5. **변경 이력** — 모든 변경이 `diary_item_history` 에 자동 적재.
6. **대량삭제 차단** — 한 번에 20줄 넘게 지워지려 하면 중단하고 경고.
7. **GitHub 백업** — 10분 간격 스냅샷.
8. **실시간 + 폴링 이중화** — 실시간 채널이 끊겨도 15초 폴링이 받아온다.
9. **첫 접속 구제** — 예전 방식으로 그 PC 에만 남아 있던 줄을 서버로 한 번 끌어올린다.

### 지워진 줄 복구하는 법

```sql
-- 최근에 지워진 줄 보기
select id, staff_name, day, text, logged_at
from diary_item_history
where deleted_at is not null
order by logged_at desc limit 50;

-- 특정 줄을 되살리기
update diary_items set deleted_at = null, client_ts = extract(epoch from now())*1000
where id = '<줄 id>';
```


## 10. 광고 컨텐츠 스튜디오 (`studio/`)

메타(인스타·페이스북) 릴스·스토리 광고용 **9:16 이미지(1080×1920)** 후가공 툴.
사진 위에 텍스트를 얹고, 실제 릴스·스토리 화면에서 **가려지는 부분(상단 바·브랜드명·캡션·CTA 버튼)** 을
반투명으로 겹쳐 보면서 피해서 배치하고, 같은 디자인으로 **대량 제작**까지 한다.

| 항목 | 내용 |
|---|---|
| 여는 곳 | 홈 → 📂 업무용 툴 → 🎬 **광고 컨텐츠 스튜디오** (새 탭) · 주소 `/studio/` |
| 잠금 | 오피스에서 PIN 을 넣은 브라우저만 열림 (`brightbeed_unlocked`) |
| 저장 | 브라우저 IndexedDB(`bb-content-studio`)에 자동 저장 — **PC·브라우저마다 따로**. 다른 PC 로 옮길 땐 `프로젝트 → 파일로 저장(.bbstudio)` → 다른 PC 에서 `파일 불러오기` |
| 결과물 | 1080×1920 JPG/PNG · 여러 장은 ZIP (UI 시뮬레이션은 결과물에 안 들어감) |

### 주요 기능
- **UI 가림 시뮬레이션** — 지면: 릴스+스토리 공통(기본, 가장 안전) · IG 릴스 · IG 스토리 · FB 릴스 · FB 스토리.
  상단 바·계정명/「광고」·캡션·CTA 버튼(더 알아보기/자세히 보기 등)·우측 아이콘·하단 메뉴를 반투명으로 표시, 불투명도 조절.
  광고 계정은 **beaduniverse** 로 고정(프로필·CTA「더 알아보기」·캡션도 고정, 편집 화면에서 못 바꿈 — `core.js` 의 `AD_PREVIEW`).

  스토리 상단 14%·하단 약 20%. 글자가 가려지면 빨간 점선 + 상태줄·페이지 썸네일에 ⚠ 경고, 저장 전에도 한 번 더 확인.

### 클로드 아티팩트 판
같은 소스로 클로드(claude.ai) 아티팩트 판도 만든다 — 오피스 밖에서도 클로드 앱에서 바로 열어 쓰는 용도.
- 만들기: `npm i -D esbuild` 후 `node studio/tools/build-artifact.mjs studio-artifact-build`
  → `studio-artifact.html`(JS·CSS 한 파일) + `fonts/`(구글 폰트가 아닌 글꼴 19종 파일) 를 아티팩트로 올림.
- 다른 점: 오피스 잠금(PIN)·「← 오피스」 링크 없음(클로드 공유 권한으로 관리), 저장은 클로드 다운로드 확인창을 거침,
  여러 장은 항상 ZIP, 프로젝트 파일은 `.bbstudio.json` (오피스판에서도 불러오기 됨). 작업물은 그 브라우저에만 저장되는 건 같음.


## 11. 메일 발송 (`mailer/`)

이메일 주소만 붙여넣으면 **한 통씩 자동으로** 보내는 툴. 제목·본문·첨부파일은 화면에서 직접 세팅한다.

| 항목 | 내용 |
|---|---|
| 여는 곳 | 홈 → 📂 업무용 툴 → 📨 **메일 발송** (새 탭) · 주소 `/mailer/` |
| 잠금 | 오피스에서 PIN 을 넣은 브라우저만 열림 (`brightbeed_unlocked`) |
| 발송 | 보내는 구글 계정(brightbeed@gmail.com)에 만든 **Apps Script 웹 앱**이 `MailApp` 으로 보냄 → 메일은 그 계정 이름으로 나감 |
| 한도 | 개인 지메일은 Apps Script 로 **하루 100명**(받는 사람 기준, 24시간마다 다시 채워짐). 화면이 남은 한도만큼만 보냄 |
| 저장 | 제목·본문·첨부 = 발송 서버(구글 계정)에 저장 → 어느 PC 에서 열어도 같음 · 연결 정보(웹 앱 URL + 발송 키) = **그 브라우저에만** |
| 기록 | 구글 시트 「브라이트비드 메일 발송 기록」 하나에 **지금까지 보낸 메일이 전부** 모임 — 툴로 보낸 메일(구분 `툴`) + 지메일에서 직접 보낸 메일(구분 `지메일 직접`, 보낸편지함에서 가져옴). 처음 연결하면 보낸편지함 전체를 가져오고, 그 뒤로는 1시간마다(시간 트리거 `syncSent`) + 화면을 열 때마다 새로 보낸 것만 이어 붙임. 시간순 정렬 · 받은 메일·임시보관·나에게 보낸 메일은 제외 · 숨김 열 「메일 ID」로 중복 방지. 화면 위 **📒 기록 시트** 버튼으로 바로 열고, 화면 아래 **📚 발송 기록**에서 검색 · 첨부는 드라이브 「브라이트비드 메일 첨부」 폴더 |
| 중복 방지 | 받는 사람을 붙여넣으면 **발송 기록 + 지메일 보낸편지함**(툴 쓰기 전에 직접 보낸 메일 포함)을 확인해서 예전에 보낸 주소는 자동으로 빼고 보냄. 서버도 보내기 직전에 한 번 더 막음. 보낸 주소는 받는 사람 칸에서 자동으로 지워짐 |

### 처음 연결 (한 번만)
1. 메일 발송 화면 → 연결 설정 → **서버 코드 복사** (이 PC 전용 발송 키가 들어간 코드)
2. brightbeed@gmail.com 으로 로그인한 상태에서 https://script.new → 붙여넣기 → 저장
3. 배포 → 새 배포 → 웹 앱 · 실행: 나 · 액세스: 모든 사용자 → 배포 → 권한 허용
4. 웹 앱 URL(`…/exec`)을 연결 설정 3번 칸에 붙여넣고 **연결**
- 다른 PC: 연결된 PC 에서 연결 설정 → **연결 코드 복사** → 다른 PC 의 3번 칸에 붙여넣기.

### 보안 메모
- 저장소가 Public 이라 **웹 앱 URL·발송 키는 절대 커밋하지 않는다.** `mailer/server.gs` 는 키 자리(`__MAIL_KEY__`)만 있는 원본이고, 키는 화면이 브라우저에서 만들어 코드에 넣어 준다.
- 서버 코드를 고치면 Apps Script 에서 `setup` 한 번 실행(권한 허용) → **배포 관리 → 수정 → 새 버전**으로 다시 배포해야 반영된다 (URL 은 그대로). 화면은 서버 버전(`SERVER_VERSION`)이 낮으면 「서버 업데이트 필요」 안내와 새 코드 복사 버튼을 띄운다.
- 서버 버전: v1 발송 · v2 기록/중복 방지 · **v3 지메일 보낸편지함 → 기록 시트 가져오기**(`importSent`, `syncSent` 1시간 트리거 — v3 은 트리거 권한이 추가돼서 업데이트할 때 `setup` 실행이 꼭 필요).
- 실제 발송 서버(brightbeed@gmail.com 「제목 없는 프로젝트」)는 `appsscript.json` 에 `oauthScopes` 를 직접 적어서 지메일은 **읽기 전용**(`gmail.readonly`)만 받는다 — 나머지: `script.send_mail`, `spreadsheets`, `drive`, `script.scriptapp`, `userinfo.email`.
- 권한 창에서 「현재 파일을 열 수 없습니다」가 뜨면 크롬에 구글 계정이 여러 개 로그인돼 있어서다(기본 계정 ≠ 스크립트 주인). 시크릿 창에서 보내는 계정만 로그인해서 승인하고, 권한 목록은 **모두 선택**.
